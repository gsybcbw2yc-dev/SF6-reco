# SF6-reco iPhone Safari実機スクリーンショットに基づくUI仕上げ
日付：2026年11月10日（JST）

## 入力と観察
ユーザー共有のiPhone Safariスクリーンショット5枚（概要上部、MR/LPグラフ、概要下部、対戦履歴MATCHUPS、分析の連敗後勝率）を目視確認。4つの主要ナビゲーションとMR中心のサマリー配置は良好で、横方向の崩れもスクリーンショット上は認められない。一方で以下の改善余地あり：
- グラフ上下面に余白が大きく、特に縦長のスマホで必要以上にページ長を占める。
- 対戦履歴画面で「対戦履歴」と「試合・セッション・キャラクター相性」が見出しとして重複。
- MATCHUPSの勝率の計算説明やMR収支算定不可が何度も表示され、勝率横棒に視線が向きにくい。
- 詳細分析の説明文が棒グラフより先に複数行を占める。
- 分析条件の案内文が「上の期間」となっていたが、フィルタは現在別の「対戦履歴」ビューにあり、記載が不適切。

## 変更と設計意図
1. `web/app.js`
   - SVG viewBox幅・高さを固定の600×210ではなく、チャートコンテナの実幅・実高から生成する。iPhoneの細い描画領域でもグラフの上下に余剰のレターボックスが発生しにくくなる。
   - 観測値が25件より多いとき、前後とも同値で変動のない中間観測点のドットを省略し、グラフの密集を軽減。実際の履歴・折れ線・時間軸は削除しない。
   - 隠れたビューでデータ更新したあと概要へ戻る場合にチャートを再描画する `window.onSf6ViewChange` を追加。表示条件・データは維持。
2. `web/view-navigation.js`
   - 概要に戻る際、新しいサイズに基づくチャートの再描画を呼び出す。既存の選択状態は維持。
3. `web/matches-ui.js`
   - 総合勝敗数・勝率の行から重複した計算式の長文を取り除き、値を最優先に。
   - MATCHUPS各キャラの概要を簡潔化。0件の引き分け・不明、すべてのカードに繰り返されていた「MR収支算定不可」は非表示に。確定MR収支が取得できれば表示。元の分析結果や計数は変更しない。
4. `web/index.html`
   - MR収支・勝率解説は「集計方法と注意事項」「キャラ相性分析の注意事項」の折りたたみに移動。
   - 高度分析4種のデータ品質やセッションについての詳細説明は `details/summary` に収納し、数値・棒グラフを先に閲覧できる構成へ。
   - フィルタ案内を「対戦履歴で設定した…」に訂正。CSS/JSのキャッシュ版番号更新。
5. `web/design-system.css`
   - iPhoneのMR/LPチャート高さを176pxに調整（旧230px）。
   - 余白・ヘッダー・MATCHUPS各カード・分析の説明開閉UIなどのサイズ・密度を精緻化。
6. `tests/test_dashboard.cjs`
   - 実際のチャート要素に幅340px、高さ176pxを設定し、描画SVGのviewBoxが `0 0 340 176` になることを回帰検査。
   - 「概要へ戻ったときの再描画」フックの提供を検証。
