## 4. 計算方法と実データ検算

### 固定時間窓

1. 選択期間・キャラクター・フェーズのMRを持つ実測点だけを時刻順に使う。フェーズ「すべて」では最後の連続した同一フェーズ区間だけを比較する。同じ番号が後で再登場しても、間の別フェーズを越えて連結しない。複数キャラクターは混ぜず、選択が「すべて」の場合は分析を保留する。
2. 日本時間の時刻境界を幅30・60・180・1440分で区切る。各境界から**5分以内に実測された点**が開始・終了の両方にある窓だけ、`終了MR－開始MR` を算出する。両点のフェーズも一致させる。境界外、欠測、フェーズ違いは「データ不足」。保存されていない時刻のMRを補間しない。
3. `MR/h = 窓のMR差 × 60 ÷ 窓の分数`。これは**時計時間あたりの定期観測差**であり、プレイ時間あたり・試合単位の変動ではない。平均速度は直近の有効な最大6窓のMR/hの算術平均。期間内の最大上昇・最大下落は有効窓だけから求める。
4. ドローダウンは選択期間内の最後の連続同一フェーズ観測列で、各点までの最高MRとその点の差の最大値。`最高から現在まで = 現在MR－期間内最高MR`、`更新に必要 = 最高MR＋1－現在MR`。最高値更新回数は最初の基準観測を含めず、その後に厳密に最高を上回った回数。最終更新時刻も表示する。

**指定された実測検算：** 公開履歴で2026-11-08 **14:00:44 JST = 1,396 MR**、**15:00:44 JST = 1,341 MR**。1時間窓14:00～15:00は両端とも境界から44秒なので有効。`1,341－1,396 = −55 MR`、`MR/h = −55`。試合ごとの経過や間の値は分からない。

2026-11-09 15:49 JSTにローカルの最新取得済み履歴15件で7日・豪鬼・60分窓を計算すると、**有効窓3/43、最大上昇＋24 MR、最大下落−55 MR、直近有効窓の平均−16 MR/h**。最高MR 1,411、現在1,368、最高から−43、更新に必要44、最大ドローダウン70 MR。固定窓に必要な観測点がなく「データ不足」になる区間が多い。公開履歴は同じ15件であることを確認した。
