run作成から collect 開始までは、それぞれ約3秒と2秒。04:36:26はcronの37分より約34秒早く表示されている。GitHub API の作成時刻を厳密な「予定イベント発生時刻」とは同一視しない。2つの run 作成時刻の差は **4時間28分11秒**。その間には旧cronの予定枠が複数存在するが、対応する `schedule` run は一覧に見つからなかった。push / 手動起動は schedule 成功に数えない。

**確認できたこと:** 観測点の間引きが原因で run が少なく見えるだけではない。Actions の `schedule` 起動自体が少ない。確認できた scheduled ジョブに長時間のキュー待ち、失敗、キャンセルはない。`concurrency: sf6-collect` と `cancel-in-progress: false` による、この2件のキャンセルもない。Actions 側の起動欠落・遅延を疑うのが妥当。

## 6. セキュリティと公開範囲

`BUCKLER_ID` は GitHub Secret から実行環境に注入し、リポジトリ、JSON、報告書、チャットには含めない。レスポンス本文・Cookie値は記録しない。HTTPステータス等の分類のみ残す。予期しない例外メッセージをそのまま保存・出力しない安全化を追加した。ただし過去のログ全件の機械的な秘密情報監査を実施したとは言えない。

公開情報：MR・LP、観測日時、収集結果と安全なエラー分類。非公開：Secret の値、Buckler のログイン情報、取得ページ本文。公開リポジトリなので戦績の長期履歴も第三者が見られる。外部スケジューラーを将来導入する場合は、Actions write 権限を持つ対象リポジトリ限定のトークンを外部に預けるリスクを本人が評価し、チャットには貼らずサービスの秘密設定に直接登録する。
